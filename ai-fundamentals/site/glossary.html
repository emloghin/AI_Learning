AI Glossary

This glossary explains the words you meet throughout AI Learn in plain language. Each entry gives a short definition, an example where it helps, and a link to the chapter that covers the idea in more depth.

A B C D E F G H I K L M N O P Q R S T V W Z

A

Acceptance criterion

An observable condition for accepting a change. Example: two simultaneous requests for the same room and time produce only one reservation. See Chapter 13.

Activation function

A small math function inside each neuron that decides how strongly it "fires", adding the non-linearity that lets networks learn complex patterns. Common ones are ReLU (turns negatives into 0) and sigmoid (squashes values between 0 and 1). See Chapter 2.

Agent

An AI system that uses a model in a loop to plan, call tools, look at the results and decide the next step until a goal is reached. Example: a coding agent that reads an error, edits a file, runs tests and repeats. See Chapter 7.

Agent skill

A folder containing a SKILL.md file, and optionally scripts and reference files, that teaches an agent one procedure. Only its name and description are loaded up front; the rest loads when a task matches. See Chapter 11.

AGENTS.md

An open, cross-tool Markdown file with instructions for coding agents, read by Copilot and many other tools. It guides an existing agent; it does not define a new one. See Chapter 11.

AI literacy

The skills, knowledge and understanding people need to use AI systems in an informed way and to be aware of their opportunities, risks and possible harms. In the EU, Article 4 of the AI Act requires providers and deployers of AI systems to take measures to support the AI literacy of their staff. See Chapter 10.

Alignment

The work of making a model behave the way people intend: helpful, honest and harmless. Techniques such as RLHF and DPO are used for alignment. See Chapter 4.

Attention

The transformer mechanism that lets each token "look at" other tokens and decide which ones matter for its meaning. In "The cat sat because it was tired", attention helps "it" connect to "cat". See Chapter 3.

B

Backpropagation

The method that works out how much each weight contributed to the error, moving backwards from the output layer to the input. Those amounts (gradients) are then used by gradient descent to update the weights. See Chapter 2.

Batch

A group of training examples processed together before the weights are updated once. A batch of 32 images means the network looks at 32 images, averages the error, then takes one learning step. See Chapter 2.

Batch API

A way to send many model requests as one job that finishes later (often within 24 hours) in exchange for a lower price, typically half. Useful for non-urgent work such as classifying thousands of reviews overnight. See Chapter 8.

Benchmark

A standard test set used to compare models, such as a collection of math problems or coding tasks. Scores are useful signals but may not reflect how a model performs on your own task. See Chapter 4.

Bias (fairness)

When an AI system treats people or groups unfairly, often because its training data under-represents them or reflects past prejudice. Example: a hiring model that scores CVs lower for one gender. See Chapter 9.

Bias (neuron)

A learned number added inside a neuron before the activation function, shifting when the neuron switches on. It plays the role of the intercept b in y = w·x + b. See Chapter 2.

BPE (Byte Pair Encoding)

A tokenization method that starts from single characters or bytes and repeatedly merges the most common neighbouring pairs into new tokens. Frequent words end up as one token, rare words as several pieces. See Chapter 3.

Branch (Git)

A separate line of work in a Git repository. You make changes on a branch, then propose merging them into the main branch through a pull request. See Setup and Git basics.

Brownfield

Work on a system that already exists, as opposed to greenfield work that starts from an empty project. Adopting Spec Kit in a brownfield project means adding the workflow around the existing code, not rewriting it. See Existing projects.

C

Chain-of-thought

Asking or allowing a model to work through a problem step by step before giving the final answer, which often improves results on maths and logic. Example prompt: "Think through this step by step, then give the answer." See Chapter 6.

Characterization test

A test that records what existing code does today, right or wrong, so that a later change which alters that behaviour is noticed. Useful before changing poorly tested code. See Existing projects.

Charter (Squad)

The file that defines one Squad team member: its role, what it owns, how it works and its boundaries. It is guidance for the agent, not an enforced permission. See Chapter 17.

Checkpoint

A saved snapshot of a model's weights at a point during training, so training can resume or an earlier version can be reused. Downloaded open models are usually checkpoints too. See Chapter 5. In coding tools the word has a second meaning: a restore point for the files an agent edited, which does not undo commands that already ran. See Chapter 12.

Chunking

Cutting documents into small passages before embedding them for retrieval. Chunk size, overlap and where the cuts fall strongly affect RAG quality. See Chapter 7.

CI/CD

Continuous integration and continuous delivery: automation that builds and tests every change (CI) and prepares or performs releases (CD). Required CI checks are one of the strongest guardrails for AI-written code. See Chapter 12.

CODEOWNERS

A file in a GitHub repository that names the people who must review changes to particular paths. Useful for protecting agent configuration files. Azure Repos offers the same effect with automatically included reviewers. See Chapter 12.

Constitution (Spec Kit)

A project's reviewed engineering principles and constraints, used to guide planning and implementation. It is not a security boundary or a replacement for feature requirements. See Spec Kit.

Context engineering

Choosing and maintaining the best set of information (instructions, tools, history, retrieved data) in the model's context at every step. It extends prompt engineering to agents and long tasks. See Chapter 9.

Context rot

The drop in how reliably a model finds and uses details from its context window as that context gets longer and noisier. Keeping prompts and retrieved text lean helps avoid it. See Chapter 8 and Chapter 9.

Context window

The maximum number of tokens a model can handle in one request, counting both input and output. Everything must fit: instructions, history, documents, the question and the answer. See Chapter 3 and Chapter 8.

Converge (Spec Kit)

The workflow step that compares the implementation with the spec, plan and tasks and appends any remaining work to the task list. It does not edit code and is not a release approval. See Spec Kit and the command reference.

Cosine similarity

A score between −1 and 1 that measures whether two embedding vectors point in the same direction: near 1 means very similar meaning, near 0 means unrelated. Used in semantic search and RAG. See Chapter 3 and Chapter 7.

Cross-entropy

A loss function for classification that measures how much probability the model gave to the correct answer; the less probability, the higher the loss. Language models are trained with cross-entropy on the next token. See Chapter 2.

Custom agent

A Markdown file that defines a specialist role for an agent: its instructions and, most importantly, the list of tools it may use. See Chapter 11.

Custom instructions

Always-on rules and project facts that an agent receives with every request, for example in .github/copilot-instructions.md. See Chapter 11.

D

Dataset

A collection of examples used to train, validate or test a model. Example: 50,000 labelled photos of cats and dogs, or trillions of tokens of web text for pretraining. See Chapter 1.

Decoder

The part of a transformer that generates output one token at a time, only looking at earlier tokens. GPT-style chat models are decoder-only transformers. See Chapter 3.

Directive (Squad)

A standing rule you give a Squad team in plain words, using signals such as "always" or "never". It is stored in the team's decisions file and read by every member. See Chapter 17.

Distillation

Training a smaller "student" model to imitate the outputs of a larger "teacher" model, keeping much of the quality at lower cost. See Chapter 4.

DPO (Direct Preference Optimization)

A preference-tuning method that learns directly from pairs of "better" and "worse" answers, without training a separate reward model as RLHF does. See Chapter 4.

E

Embedding

A list of numbers (a vector) that represents the meaning of a token, sentence or document, so that similar meanings are close together. Embeddings power semantic search and RAG. See Chapter 3 and Chapter 7.

Encoder

The part of a transformer that reads the whole input at once and builds a representation of it, looking in both directions. BERT is an encoder-only model often used for classification and search. See Chapter 3.

Environment variable

A named value that the operating system passes to programs, often used for settings and secrets so they do not have to be written into files. In PowerShell: $env:NAME = "value". See Setup and Git basics.

Epoch

One complete pass through the entire training dataset. Training for 10 epochs means the model has seen every example 10 times. See Chapter 2.

Evaluation

Measuring how well a model or AI feature performs, using test sets, automated checks, human review or another model as a judge. Good evaluation is how you know a change made things better. See Chapter 6 and Chapter 9.

F

Few-shot

Including a few worked examples in the prompt so the model copies the pattern. Example: three "review → sentiment" pairs followed by a new review to label. See Chapter 6.

Fine-tuning

Continuing to train an existing model on a smaller, specific dataset to adapt it to a task, style or domain. See Chapter 4.

FLOPs

Floating-point operations: the count of basic arithmetic steps a computer performs. Used to describe how much compute training a model takes (total FLOPs) or how fast hardware is (FLOPs per second). See Chapter 4.

Foundation model

A large model pretrained on broad data that can be adapted to many tasks, such as the base models behind chat assistants. See base models in Chapter 4.

Frontmatter

A block of key: value settings between two --- lines at the top of a Markdown file, written in YAML. Skills, custom agents and path-specific instructions use it. See Chapter 11.

Function calling

A feature where the model, instead of answering in text, returns a structured request to run one of your functions (for example get_weather(city="Paris")). Your code runs it and sends the result back. Also called tool calling. See Chapter 7.

G

GGUF

A file format for storing (often quantized) model weights so they can run efficiently on ordinary computers with tools like llama.cpp and Ollama. See Chapter 5.

Golden set

A fixed collection of real inputs with known good answers, used to re-test a prompt or model after every change. See Chapter 6.

GPU

Graphics Processing Unit: a chip with thousands of small cores that do many multiplications in parallel, which makes it ideal for training and running neural networks. See Chapter 2 and Chapter 4.

Gradient

A set of numbers that says, for each weight, which direction and how strongly changing it would increase the loss. Training moves weights the opposite way. See Chapter 2.

Gradient descent

The training method that repeatedly nudges weights a small step in the direction that reduces the loss, like walking downhill in fog. See Chapter 2.

Greenfield

A project that starts from an empty folder, as opposed to brownfield work on an existing system. See Chapter 14.

Guardrails

Checks and limits around an AI system that block or correct unsafe or unwanted inputs and outputs, such as content filters, output validation or approval steps. For agents, the dependable guardrails are enforced outside the model: tool permissions, sandboxing, hooks and required reviews. See Chapter 9 and Chapter 12.

H

Hallucination

When a model produces confident but false or made-up information, such as a citation to a paper that does not exist. It happens because models predict likely text, not verified facts. See Chapter 3.

Harness

The program around a model that runs the agent loop: it reads files, calls tools, asks for approvals and manages context. GitHub Copilot in VS Code and the Copilot CLI are harnesses. The model is the reasoning engine inside it. See Chapter 11.

Hook

A script that an agent host runs automatically at a fixed point, such as before every tool call. Because it is ordinary code, the model cannot talk its way past it. See Chapter 12.

I

Idempotency

The property that repeating an operation has the same business effect as performing it once. Important for retrying requests and processing duplicate payment notifications. See Shipping and Reuse.

Inference

Using a trained model to make predictions or generate output, as opposed to training it. Every chat message you send triggers inference. See Chapter 1.

Instruction tuning

Fine-tuning a base model on examples of instructions and good responses so it learns to follow requests instead of just continuing text. See Chapter 4.

K

Knowledge cutoff

The date after which a model has no training data. It does not know later events unless you supply them in the prompt, through retrieval or with a search tool. See Chapter 3.

KV cache

Stored "key" and "value" results from attention for tokens already processed, so the model does not recompute them when generating each new token. It speeds up generation but uses memory. See Chapter 3.

L

Latency

How long you wait for a response. Often split into time to first token (affected by input size) and total time (affected by output length). See Chapter 6 and Chapter 8.

Layer

A group of neurons that process data at the same stage; data flows from the input layer through hidden layers to the output layer. "Deep" learning means many layers. See Chapter 2.

Learning rate

The size of each step gradient descent takes when updating weights. Too large and training jumps around or diverges; too small and it crawls. See Chapter 2.

Lethal trifecta

Simon Willison's name for the dangerous combination in one agent of access to private data, exposure to untrusted content and the ability to communicate externally. See Chapter 12.

LLM (Large Language Model)

A neural network, usually a transformer, trained on huge amounts of text to predict the next token, with billions of parameters. Examples include the models behind ChatGPT, Claude, Gemini and Copilot. See Chapter 3.

LoRA (Low-Rank Adaptation)

A parameter-efficient fine-tuning method that freezes the original weights and trains small add-on matrices instead, making fine-tuning far cheaper. See Chapter 4.

Loss

A single number that measures how wrong the model's predictions are; training tries to make it smaller. See Chapter 2.

M

MCP (Model Context Protocol)

An open standard that lets AI applications connect to tools and data sources through "MCP servers" in a consistent way, like a USB-C port for AI tools. See Chapter 7.

Model card

A document published with a model describing its intended use, training data, evaluation results, limitations and license. See Chapter 5.

MoE (Mixture of Experts)

A model design with many "expert" sub-networks where a router activates only a few for each token, so the model can have many parameters but use only some per step. See Chapter 4.

Multimodal

A model that can handle more than one type of data, such as text plus images, audio or video. Example: asking a model to describe a photo. See Chapter 3 and Chapter 6.

N

Neural network

A model made of layers of connected artificial neurons whose weights are learned from data. See Chapter 2.

Neuron

The basic unit of a neural network: it multiplies its inputs by weights, adds a bias, and passes the result through an activation function. See Chapter 2.

O

Open-weight

A model whose trained weights are published for download, so you can run it yourself, even if its training data and code are not released. See Chapter 5.

Overfitting

When a model memorizes its training data, including noise, and performs poorly on new data. Like a student who memorized past exam answers but cannot solve new questions. See Chapter 1 and Chapter 2.

P

Parameter

A number inside the model that is learned during training, mainly weights and biases. "7B" means about 7 billion parameters. See Chapter 2.

PATH

The list of folders your terminal searches for programs. If a freshly installed command is "not found", its folder is usually not on PATH yet, or the terminal needs to be reopened. See Setup and Git basics.

Perplexity

A measure of how "surprised" a language model is by a piece of text; lower perplexity means it predicts the text better. Not covered in depth on this site; related: evaluation and benchmarks in Chapter 4.

Pretraining

The first, most expensive training stage, where a model learns general patterns of language from massive amounts of text by predicting the next token. See Chapter 4.

Prompt

The input you give a model: instructions, context, examples and the question. See Chapter 6.

Prompt caching

A provider feature that reuses the already-processed beginning of a prompt when later requests start with the same tokens, making them cheaper and faster. Put stable content first to benefit. See Chapter 8.

Prompt injection

An attack where text in the input, or in content the model reads such as a web page or email, tries to override the app's instructions. It is number one on the OWASP Top 10 for LLM Applications. See Chapter 9.

Pull request (PR)

A proposal to merge the changes on one branch into another, with a place for review, discussion and automated checks. It is the main point where a person approves AI-written code. See Setup and Git basics.

Q

Quantization

Storing a model's weights with fewer bits (for example 4-bit instead of 16-bit) to cut memory and speed up inference, usually with a small loss in quality. See Chapter 4 and Chapter 5.

R

RAG (Retrieval-Augmented Generation)

A pattern where your app first searches your own documents for relevant passages and adds them to the prompt, so the model answers from that information. Example: a bot answering questions from a company handbook. See Chapter 7.

Reasoning model

A model trained to "think" through problems internally, producing hidden reasoning tokens before its final answer. Better on hard problems, but slower and more expensive. See Chapter 3 and Chapter 8.

Reasoning tokens

The hidden "thinking" tokens a reasoning model generates before answering. You do not see them, but they use context space and are billed as output tokens. See Chapter 8.

Reinforcement learning

A type of learning where an agent tries actions, receives rewards or penalties, and learns to maximize reward over time. See Chapter 1.

Reranking

A second step in search that reorders retrieved results with a more accurate model so the best few go into the prompt. See Chapter 7 and Chapter 8.

RLHF (Reinforcement Learning from Human Feedback)

A tuning method where humans rank model answers, a reward model learns those preferences, and the language model is trained to produce answers the reward model scores highly. See Chapter 4.

S

Sampling

How a model picks the next token from its probability list. Settings such as temperature and top-p control how random the choice is. See Chapter 3.

Sandbox

An isolated environment that limits what a program can read, change or reach over the network. Running an agent's commands in a sandbox limits the damage a mistake or a prompt injection can cause. See Chapter 12.

Self-supervised learning

Learning where the training data provides its own labels by hiding part of the input and asking the model to predict it — such as hiding the next token of real text during LLM pretraining. No human labelling is needed. See Chapter 1 and Chapter 4.

SFT (Supervised Fine-Tuning)

Fine-tuning on example prompts paired with high-quality answers written or approved by people. It is usually the first step in turning a base model into a chat model. See Chapter 4.

Softmax

A function that turns a list of raw scores into probabilities that are all positive and add up to 1. Used at a model's output and inside attention. See Chapter 2 and Chapter 3.

Spec drift

The situation where the written requirements and the actual behaviour of the software no longer agree. See Chapter 13.

Spec Kit

GitHub's toolkit of CLI commands, templates, scripts and agent instructions for structured development processes. Its SDD workflow carries a feature specification through implementation and completeness assessment. See Spec Kit.

Spec-driven development (SDD)

A development approach in which explicit requirements guide planning, implementation and verification. A useful spec describes observable behaviour and boundaries rather than vague aspirations. See Chapter 13.

Squad

An open-source toolkit for coordinating AI-agent teams with repository-based roles, routing and shared context. A team remains under human direction; multiple agents do not guarantee correctness or isolated edits. See Squad.

Stop sequence

A string that tells the model to stop generating when it appears, such as "\n\n" or "END". Useful for keeping outputs short. See Chapter 8.

Streaming

Sending a model's answer piece by piece as it is generated, so the user starts reading after the first token instead of waiting for the last. See Chapter 6.

Structured output

Asking a model to reply in a fixed format, usually JSON that matches a schema, so your code can read it reliably. See Chapter 6.

Subagent

A helper agent that the main agent hands a task to. It works in its own context and returns only its result, which keeps the main conversation short. See Chapter 11.

System prompt

Instructions given to the model with higher priority than user messages, setting its role, rules and style for the whole conversation. See Chapter 6.

T

Temperature

A sampling setting that controls randomness: low values make answers more predictable, high values more varied and creative. See Chapter 3.

Token

The unit of text a model reads and writes, often a word or part of a word. In English, 1 token is roughly 4 characters or ¾ of a word. See Chapter 3 and Chapter 8.

Tokenizer

The component that splits text into tokens and maps them to numbers (and back). Different model families use different tokenizers. See Chapter 3.

Tool calling

Another name for function calling: the model returns a structured request to run a tool (for example a search, database query or MCP tool), your application runs it, and the result is fed back to the model. See Chapter 7.

Top-p

A sampling setting (nucleus sampling) that limits choices to the smallest group of tokens whose probabilities add up to p, for example 0.9. See Chapter 3.

Training

The process of adjusting a model's parameters using data so its predictions improve. See Chapter 1 and Chapter 4.

Transformer

The neural network architecture behind modern LLMs, built around attention so every token can consider every other token in parallel. Introduced in the 2017 paper "Attention Is All You Need". See Chapter 3.

V

Vector database

A database built to store embeddings and quickly find the ones most similar to a query, used for semantic search and RAG. See Chapter 7.

W

Weights

The learned numbers on the connections between neurons that determine how strongly each input influences the output. "Downloading a model" mostly means downloading its weights. See Chapter 2.

Z

Zero-shot

Asking a model to do a task with no examples in the prompt, relying only on instructions. Example: "Classify this review as positive or negative." See Chapter 6.
