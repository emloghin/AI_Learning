About This Exam

The GH-600: Developing in Agentic AI Systems exam (credential: GitHub Certified: Agentic AI Developer) validates your ability to operate, integrate, supervise, and govern AI agents inside production-grade SDLC (Software Development Lifecycle) workflows using GitHub as the system of record and control plane.

Unlike feature-based certifications, GH-600 is role-based and scenario-driven. You won't be tested on memorizing documentation — you'll be asked to make architectural decisions about agent systems.

The Six Exam Domains

The exam tests six skill areas. Study proportionally: Domain 2 is the heaviest at 20–25%.

Domain 1 · 15–20%

Prepare Agent Architecture and SDLC Processes

Integrate agents into the SDLC, define boundaries between planning, reasoning, and action, configure observability and control (autonomy, inspectable artifacts, human intervention) for autonomous agents.

Weight: 15–20%  Study this domain →
Domain 2 · 20–25% ★ Heaviest

Implement Tool Use and Environment Interaction

Select and configure agent tools, MCP servers, CI integration, safe execution paths, and error handling.

Weight: 20–25% ★ Heaviest  Study this domain →
Domain 3 · 10–15%

Manage Memory, State, and Execution

Implement memory strategies, persist agent state, manage context drift, ensure continuity across tools.

Weight: 10–15%  Study this domain →
Domain 4 · 15–20%

Perform Evaluation, Error Analysis, and Tuning

Define success criteria, analyze failures, tune agent behavior through instructions, tools, and environment changes.

Weight: 15–20%  Study this domain →
Domain 5 · 15–20%

Orchestrate Multi-Agent Coordination

Operate multi-agent workflows, isolate execution, detect conflicts, ensure observability, recover from failures, and manage agent lifecycle in multi-agent systems.

Weight: 15–20%  Study this domain →
Domain 6 · 10–15%

Implement Guardrails and Accountability

Define risk-based autonomy levels, implement guardrails and human-in-the-loop workflows, enforce least privilege, and require controlled paths for irreversible changes.

Weight: 10–15%  Study this domain →

Microsoft Reactor Deep Dive — Key Takeaways

Based on Ari Levigny's (GitHub Sr. Developer Advocate) 1-hour exam walkthrough. These are quotes and emphasis points from the video (unverified community info, except where an official source is cited).

Core mantra — "Trust but verify": "Evaluate the work by the standards of the workflow, not by the novelty of the author. The human and the policy accept the agent's proposals." Agents propose, humans and rulesets decide what gets merged. (The "standards of the workflow" sentence matches the official contributor model unit; "agents propose; humans and policy accept" matches Map agent responsibilities to the SDLC.)

Plan → Act → Evaluate is the heartbeat: Plan your architecture, let agents act within scoped tools, then evaluate via checks and scans. Feed the evidence back into the plan. It's a cycle, not a straight line. (Matches the official agent lifecycle unit.)

Domain 2 is the bulk of the exam: Ari explicitly says "spend a lot of time on the Tooling module." Planning agents should be read-only (just read/search). Execution agents (coder, designer) get edit/execute. Always ask: what is the least privilege needed?

Context rot / context drift is tested: When the context window gets too full, the model struggles and drifts from the main goal. Domain 3 tests your ability to manage memory expiration, pruning, and session resumption.

Multi-agent orchestration is a skill to learn for real work: "Not just for the exam." Orchestrator → Planner → Coder + Designer working in parallel on isolated branches. Each agent gets its own branch, proposes a PR, runs checks. Never merge to main directly.

Governance = least privilege + rulesets + CODEOWNERS + environment gates: Ari emphasizes "you got to understand what does least privilege mean." The agent operates in isolated branches with tightly scoped workflow permissions, branch policies, and rulesets. Required scans (CodeQL), human-in-the-loop via CODEOWNERS, and deployment approvals.

⚠️ Execution without validation = anti-pattern: "If an agent can bypass required checks or merge without reviews, the architecture loses its primary safety mechanisms." Always keep human review + status checks + rulesets between the agent and main. (Verbatim from the official PR governance unit.)

Actions knowledge needed — but not deep YAML: You need to understand how agents touch GitHub Actions (evaluating workflows, fixing errors in workflows). You don't need to know every YAML key or action detail. High-level understanding is enough.

Beta exam counts — no retake needed at GA (historical): If you passed the beta, you're grandfathered in. The beta was for Microsoft to collect feedback on ambiguous questions. Results took ~8 weeks. Certification validity is 2 years (per the official certification page; the video's "~2–3 years" was imprecise).

Hands-on practice is how you learn: "Reading and videos are great, but hands-on practice really drives the point home." Do the GitHub Skills, run the Microsoft Learn modules, and use the exam sandbox (ghcertdemo.starttest.com or aka.ms/examdemo).
